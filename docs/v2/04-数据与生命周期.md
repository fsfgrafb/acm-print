# 数据与生命周期

## 1. 数据模型草案

此处定义职责和约束，不是最终 SQL。所有内部 ID 使用 UUID，时间存 UTC timestamptz，界面显示 Asia/Shanghai；学号使用 text。外部文件路径保存受控相对键，不由客户端决定路径。

| 实体 | 核心字段/约束 |
|---|---|
| system_state | 单行初始化完成标志、唯一 admin_subject_id、手动暂停、配置版本；初始化成功不可自动复位 |
| subjects | id、student_id 唯一、password_hash、must_change_password、status、邮箱/phone、created_at、expires_at；管理员由单例引用判定 |
| sessions | token 摘要、subject_id、expires_at；重置/封禁/转让撤销会话 |
| blobs | SHA-256、byte_size、storage_key、media_type、生命周期状态；物理内容去重 |
| documents | 原件 blob、首次标准 PDF blob、转换器版本、标准 PDF 哈希/页数、处理状态 |
| document_grants | subject_id、document_id、显示文件名及授权来源；去重与授权分离 |
| batches | owner_id、提交序号、创建时间、幂等关联 |
| print_tasks | batch_id、position、document_id、标准 PDF 版本、page_numbers 整数数组、copies、方向/缩放、printer_id、state、parent_task_id；参数提交后不可变 |
| submission_attempts | task_id、唯一 marker、通用 job 引用、提交时间、原始状态/错误及对账时间；操作诊断用途 |
| print_history | task_id 唯一、subject_id、文件名快照、系统提交时间、total_pages；获得 JobId 时创建 |
| derived_cache | 标准 PDF 哈希、选页列表/版面参数摘要、产物键、最后访问时间、生成状态 |
| idempotency_entries | subject_id + key 唯一、请求摘要、batch_id、结果/墓碑及过期时间 |
| settings | 网页可管理的数值配置、版本、更新时间；部署配置另从新版 config/platform.toml 加载，不复用旧 config.toml |
| maintenance_operations | 删除意图、保护引用、失败原因和重试进度；不得自动成为永久个人审计账本 |

标准 PDF 与原件相同字节时可引用同一 blob，计量仅算一次。角色转让锁定 system_state 单行、验证目标资格并更新引用；事务内撤销原管理员会话，杜绝零管理员/多管理员的中间状态。

## 2. 文件一致性与动态产物

原件和首次标准 PDF 持久化且不可变；选页 PDF、版面打印产物、页面图片是缓存。首次标准 PDF 不是可随意重建的缓存，不因转换器升级替换历史版本。

选页语义 PDF保留原文尺寸；打印版面计划在 A4 上应用方向、actual/fit 和可打印区域。预览图片与打印渲染使用同一版面计划，避免 PDF 下载被再次 fit 导致二次缩放。下载“打印 PDF”为单份 A4 版面结果，原件下载单独提供。几何算法和裁切需尺量验收。

缓存键必须含标准 PDF 哈希、有序含重复页码、版面参数、设备几何版本、渲染器版本及 DPI（页面图片）；不含份数，因为文件为一份。并发生成使用唯一键与认领状态，完成后原子归位；失败不留 ready 标记。

活动任务持有原件/标准 PDF/需要的派生文件引用保护；清理不能仅按目录文件年龄删除。文件删除为可重试操作：先持久标记、阻止新引用、确认无保护后删除物理内容，再完成记录清理。允许失败重试和孤儿检查，不在数据库事务中长时间删除大量文件。

## 3. 去重与访问权

先支持本人已授权原件按哈希免传：服务端返回本人 document 引用，用户重新设置选页。浏览器计算哈希用于 lookup；新上传在服务端流式计算并校验。

跨学号不通过 lookup 泄露存在性；用户实际上传后服务端可按哈希复用同一物理 blob，并建立本人独立 grant。删除某成员引用不影响其他成员的合法使用；最后引用和活动保护解除才物理删除。

未提交的上传按临时期限清理；原件不是无期限个人网盘。成功提交历史保留其文档引用，再次打印使用该授权。处理失败或排队取消但从未获得 JobId 的文档按临时规则到期清理，活动引用保护期间除外。

## 4. 容量策略

默认总上限 512 GB（十进制 512,000,000,000 字节），目标水位 90%，均可管理员修改。计量包括专用应用数据库磁盘占用、原件、首次标准 PDF、派生缓存和应用临时文件；按实际物理文件去重计数。部署备份放独立位置，不计入应用上限，但须单独磁盘空间监测。

超限先清理闲置可重建缓存；仍超限按最早成功系统提交时间清理已结束历史及独立引用，直到降至目标水位。不能清理活动任务。若共享文件导致删一条记录不释放物理空间，继续其他可清理记录并显示实际释放量。

数据库删除行不会立即缩小物理文件。测量同时展示数据库物理占用、可复用空间、文件占用和空闲磁盘；普通维护用常规 VACUUM，不为达到阈值反复自动执行阻塞式全库重写。如果物理上限始终无法达到，提示维护需要并拒绝新上传，不假装清理完成。

提交、上传、转换均做容量预留/余量检查，预估转换无法保证最终体积，产物写入过程中也受预算限制。活动文件无法清理且空间不足时拒绝新上传，不损坏已有任务。实际磁盘剩余量是独立约束，不以 512 GB 额度替代。

## 5. 到期、清理与备份

到期先撤销身份访问，再按状态文档处置活动作业，删除历史、任务个人数据、授权引用、会话及主体。同学号重导入不能继承旧 UUID 授权。唯一管理员延期仅用于完成交接，交接后若已到期进入同一清理流程。

空间清理历史后不保留隐藏累计统计；未删除记录重新计算统计。幂等墓碑只保存必要摘要并限期清理，防止清理后网络重试再次出纸；主体删除时撤销其墓碑与访问能力。

设计默认：内部运行诊断及配置操作记录保留 30 天；主体删除时移除个人关联/敏感字段。备份默认每天生成、滚动保留 7 天，恢复时先运行到期检查再开放登录和打印。在线库的删除不承诺立即从历史备份逐条抹除；此备份窗口须在部署说明清楚展示。

备份含数据库和对应不可变文件清单，缓存可不备份；禁止只有 pg_dump 没有原件/标准 PDF。备份期间协调清理，避免清单引用的文件先被删；恢复校验哈希、引用及初始化标志。旧系统数据不迁移。
