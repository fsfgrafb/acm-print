# 任务状态与恢复

## 1. 三个独立状态维度

文件准备状态、应用打印任务状态、设备阻塞原因分别保存。缺纸不是提交未知；管理员暂停也不是设备故障。

文件状态为 receiving → processing → ready，失败为 failed。只有 ready 文件且有效的渲染计划能进入打印提交。准备失败显示在提交页，不能成为正常打印历史。

| 任务状态 | 含义及允许动作 |
|---|---|
| queued | 已持久入应用队列，尚未调用设备；可安全取消 |
| submitting | 正在提交驱动，可能已产生外部副作用；不能直接标取消或重发 |
| submitted | 已取得并持久保存系统作业引用，产生正常历史 |
| printing | 作业仍在系统队列处理；支持能力验证后的取消 |
| cancelling | 已请求取消，等待系统结果；不可提前显示取消成功 |
| queue_ended | 曾确认提交的作业已从可用队列查询中消失；不承诺实际出纸 |
| cancelled | queued 原子取消，或底层确认取消请求后作业移除；可能已出部分纸 |
| failed | 能确定没有提交的失败；设备正常时继续其他任务 |
| unknown | 无法确定提交或结束结果；不自动重发，管理员决定补打 |

状态标签可更友好，数据库语义不随界面文案改变。系统查询失败不能作为作业消失证据；job_id 应同时匹配队列及唯一文档标记，防止编号复用误认。

## 2. 提交和历史事务

1. 请求用学号主体 ID、幂等键和规范化参数摘要查重。
2. 同键同参数返回原批次；同键不同参数返回冲突。数据库唯一约束保证多 API 进程一致性。
3. 事务创建批次、逐文件任务及参数快照；顺序固定。完成响应后即使客户端离线也可继续执行。
4. worker 原子认领 queued 并记录提交尝试和唯一文档标记，再调用驱动。
5. 获得 JobId 后事务保存通用作业引用，标记 submitted，并创建唯一成功提交历史。后续状态更新不重复创建历史。

StartDocW 已取得 ID、后续页渲染或 EndDoc 出错时，已经产生外部作业，应保存 ID 和错误、尝试 AbortDoc/取消并对账；不得归为“确定未提交”。

正常历史仅在获得系统 JobId 后产生；API 返回 queued 不算成功提交。取消、失败、未知在内部运行任务中保留以便恢复，未取得 JobId 的记录不进入正常历史统计。

幂等覆盖应用任务创建；驱动不参与数据库事务，不能承诺无条件 exactly-once。提交窗口崩溃依靠对账与 unknown 策略防止盲目重复。

设计默认：幂等登记在对应批次/历史被清理后保留无文件内容的摘要墓碑 30 天，过期后客户端必须创建新操作键；现有请求重试不能把“已清理”当作“从未提交”。该期限可管理配置。

## 3. 顺序与份数

批次按持久提交序号排序，批内按 position；只提交 ready 文件，失败文件由用户决定是否另批提交。不因转换完成先后改变顺序。

第一版一个打印 worker 串行提交并跟踪当前可确认作业。逐份顺序在一份作业中按应用循环实现，驱动 copies 固定 1，避免 double copies。PDF 预览和下载呈现一份，worker 对其按份数重复页面序列。

当前作业 queue_ended/cancelled/确定失败后取下一任务。unknown 不阻塞正常设备下的后续任务；仍持续对账可重新发现原作业，但不重提交原 PDF，可能存在真实设备队列顺序与应用预期不一致，管理员界面需显示未知提醒。

## 4. 阻塞和恢复

调度条件：管理员未暂停、设备状态查询可用且无阻塞、独占 worker 有效、存储可用。

| 情况 | 处理 |
|---|---|
| 管理员暂停 | 停止后续提交，已在系统队列的作业继续；只能管理员恢复 |
| 缺纸、卡纸、离线等设备故障 | 停止新提交，保留已提交作业；故障解除自动继续，不能解除手动暂停 |
| 现场补纸并点击驱动继续 | 跟踪同一作业，不重发 |
| 任务自身确定失败、设备正常 | 标记失败，继续后续 |
| 提交超时/崩溃窗口 | 对账唯一标记；匹配则补存 JobId，无可靠证据则 unknown |
| 队列查询不可用 | 显示状态未知，阻塞新提交；不推断全部任务结束 |
| 作业消失且曾取得 ID | queue_ended；若本平台取消请求已被确认则 cancelled |

碳粉低仅警告、不自动阻塞，为设计默认；可靠的耗尽状态可作为阻塞。实际驱动能力待验证，遥测不可用显示未知，不以默认 false 伪装充足。

## 5. 取消、再次打印及到期

queued 取消用状态条件更新，与 worker 认领互斥。submitting 取消记取消意图，待 JobId 获得后处理；期间显示等待提交确认。底层取消失败或结果不明保持原状态/unknown，不能只改本地 cancelled。

在印取消需能力验证；报告只证明暂停作业删除，不证明进纸后每页可撤回。界面注明已出纸部分无法撤回。

再次打印、补打仅返回提交页初始化数据；用户确认创建新批次，关联 parent_task_id。沿用原件及首次标准 PDF，选页使用原文页码，可修改参数，不自动复制旧幂等键。

学号到期撤销会话、禁止新操作、取消 queued。submitting 待对账，已提交作业结束后清理。unknown 进入待清理维护列表；设计默认 24 小时后再次核对队列，仍无匹配且设备可查询则解除文件保护，执行到期清理，不重新提交。查询持续不可用需管理员在本地核实后解除保护，不自动删除可能仍被设备使用的数据。这个异常处置期限可管理配置。
