## 2. 全面重构的边界

| 方面 | 旧版参考现状 | 新版实施依据 |
|---|---|---|
| 前端 | 原生 JavaScript、HTML/CSS，hash 路由及 DOM 渲染 | React + TypeScript + Tailwind CSS，重新组织组件与状态 |
| 后端与数据 | Rust/Axum 单进程、SQLite、进程内锁与后台任务 | FastAPI、PostgreSQL，API/文档处理/打印/维护分进程，数据库约束与协调 |
| 打印 | 平台打印调用及系统队列跟踪 | 通用适配接口；Windows 首版采用 PDFium → RGB → Pillow DIB → GDI，持久记录与对账 |
| 身份初始化 | 默认管理员及旧配置初始化 | 前端填写首任管理员，原子初始化，完成后不可重开 |
| 配额与审批 | 每日额度、超额审批、审核中心、拆页提醒 | 全部移除，以任务记录和现有权限矩阵为准 |
| 任务状态 | 旧状态、作业跟踪和结束处理 | 文件、任务、设备阻塞三个维度；未知不重发，队列结束不等于实际出纸 |
| 数据与文件 | 旧数据库、上传及预览记录 | 新 schema 和引用生命周期；不迁移旧数据，不沿用旧目录作为新版存储 |
| 业务名称 | 页面标题、登录及侧栏有固定业务名称 | 统一读取新版业务命名配置，见命名配置契约 |

全面重构不要求复制旧模块、路由、状态字符串或配置格式；既有新版契约中的 `student_id` 等稳定字段按新版定义实现。旧源码用于理解使用场景和识别问题，不作为新版依赖或兼容层。

## 3. 前端布局参考

源码可见的旧版布局包括桌面侧栏加主内容区、登录区域、提交页文件列表及辅助区、队列任务卡片、用户管理表格、预览弹窗和通知区。可以借鉴信息层级、导航与内容分区，但不要求像素复刻、复制样式或保留动画。

新版普通成员保留提交打印、任务队列、个人设置三个页面，管理员增加用户管理、系统管理两个页面。提交页以文件准备、批量排序、逐文件参数和选页预览为主，不保留今日额度与审批提示。共享队列按新版服务端字段授权展示，不能因旧布局存在预览按钮而开放权限；状态展示使用新版状态语义。

手机版布局、拖动及上移/下移操作、分页历史、方向与缩放高级设置，按新版需求重新设计。旧版品牌文字和图标不作为新业务品牌要求；若新增品牌资产或业务专属说明，应继续集中配置，避免在页面组件里写死。
