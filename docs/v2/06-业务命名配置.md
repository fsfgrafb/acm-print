# 业务命名配置

基线日期：2026-10-14。按新增需求，业务名称集中在配置文件中，方便后续用于其他业务。本文定义实现契约；配置加载、公开命名接口和前端页面已开始按此实现，完整状态见[实现进度](../implementation.md)。

## 1. 配置来源与范围

使用新版本地部署文件 `config/platform.toml`，格式为 UTF-8 TOML。首次部署从 [platform.example.toml](../../config/platform.example.toml) 复制后修改。生产配置由部署者维护，业务名称不进入构建时环境变量，不由数据库 `settings` 或网页管理页覆盖。

| 配置键 | 用途 | 校验 |
|---|---|---|
| `branding.platform_name` | 浏览器标题、应用标题、登录及首次设置标题、适用的导出文件名前缀 | 非空字符串，去除首尾空白后 1–80 个 Unicode 字符 |
| `branding.organization_name` | 展示所属组织的说明和页脚；页面需要组织名称时统一使用 | 非空字符串，去除首尾空白后 1–80 个 Unicode 字符 |
| `branding.identity_label` | 身份输入框、队列列标题、设置、导入提示、管理员交接、校验错误中的身份显示名称 | 非空字符串，去除首尾空白后 1–20 个 Unicode 字符 |
| `branding.logo_url` | 集训队/业务 Logo | 本地 `/brand/` 下的 SVG、PNG、WebP 或 ICO 文件；默认 `/brand/team-logo.svg` |
| `branding.icon_url` | 网站图标 | 同样限制本地品牌资源；默认 `/brand/favicon.svg` |

三个名称字段均必填，两个品牌资源字段采用表中默认路径，部署者可独立设置平台和组织名称；不能从平台名截取组织名或拼接固定业务前缀。配置文件缺失、字段缺失、非字符串、空字符串、超长值、未知键或控制字符均在 API 启动时明确报错，不回退到硬编码业务名。新版配置还包含严格定义的 server、storage、printer 和 converter 部署段，不能将这些段传给公开命名接口。启动日志可指出配置键和原因，不输出整个配置文件。

这份配置仅用于名称展示，不允许指定可执行脚本、HTML 模板或任意程序路径。既有四年期限、唯一管理员、A4 单面及文件权限不随名称变化；显示“工号”时仍遵守同一身份校验和期限规则。标识字段、CSV 必需列 `student_id`、路由、错误 code、数据库键及本地工具参数保持现有契约，不翻译成配置字符串。

## 2. 加载与前端传递

API 使用统一配置模块加载并校验文件。相对配置路径相对于部署应用根目录解析，不依赖启动 shell 的工作目录；部署可通过 `PLATFORM_CONFIG_FILE` 指定绝对配置路径。未设置时读取应用根目录下的 `config/platform.toml`。

`GET /api/public/branding` 无需登录，使用字段白名单返回以下结构，五项字段值来自已校验配置：

```json
{
  "platform_name": "<配置的平台名称>",
  "organization_name": "<配置的组织名称>",
  "identity_label": "<配置的身份显示名称>",
  "logo_url": "/brand/team-logo.svg",
  "icon_url": "/brand/favicon.svg"
}
```

该接口不得序列化完整配置对象，不返回数据库凭据、磁盘路径、初始化凭证或打印驱动细节。初始化前后都可读取，避免首次设置和登录页面出现写死的名称。

前端在应用启动时获取一次公开命名快照，统一供页面和浏览器标题使用；获取完成前显示通用“打印平台”加载状态，失败时显示可重试的加载错误，不显示旧业务名称。服务端身份校验消息使用同一 `identity_label`，前端不按字符串替换整段后端消息。以纯文本渲染配置值，不使用 HTML 注入。

业务命名不热更新。修改文件后重启 API，浏览器刷新重新获取；接口使用 `Cache-Control: no-store`，前端不将名称长期存于本地存储或构建产物。多 API 进程读取同一文件，部署时统一重启，不允许不同实例长期使用不同命名。

## 3. 使用边界

- 浏览器标题、应用标题、登录、首次设置和导航的业务名称统一读取配置。
- 组织说明、页脚及后续新增的业务名称文案统一读取配置，不增加业务专属常量。
- 身份文案使用配置值，例如“请输入{identity_label}”“首任管理员{identity_label}”。CSV 格式说明同时明确稳定列名 `student_id`，下载模板仍用该列名。
- 统计导出文件名若包含平台名称，使用当前配置并做跨 Windows/Linux 的安全文件名处理：替换路径分隔符、控制字符和非法字符，避免保留设备名并限制长度；CSV 列名和数据结构保持稳定。
- 用户原始文件名、历史文件名快照、文档内容及数据目录键不做业务名称替换；作业唯一标记使用稳定技术标识，不依赖显示名称，以免改名影响对账。

正式文档使用通用平台名称；具体业务名称仅在示例配置中出现。原业务的需求说明、身份语义和设备型号是当前设计背景，不能把设备型号或技术名误当作品牌字符串替换。

## 4. 实施验收

用一份临时配置将平台名设为“办公室打印平台”、组织名设为“行政部”、身份显示名称设为“工号”。只重启 API 并刷新页面，检查初始化、登录、提交、队列、个人设置、用户管理、系统管理、浏览器标题、校验提示和导出命名；前端无需重新构建，页面中无旧业务名或写死的身份标签。

验证缺失配置及非法字段启动失败、公开响应不泄露部署配置、特殊字符按文本显示，以及更换名称后原 CSV 导入、身份授权、历史访问和作业对账仍沿用稳定字段。此为未来实现验收项，当前文档修改不代表运行功能已通过测试。
