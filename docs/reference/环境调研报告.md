# Windows 打印平台环境调研报告

调研日期：2026-10-13，Asia/Shanghai。地点：目标 Windows 主机本机。所有文档均为本次生成的合成测试数据。

## 1. 结论与推荐实现

这台主机已经具备运行 **Python FastAPI + React 打印平台** 的基础条件。Python/Node 可运行，React 构建通过，FastAPI 真实 HTTP 接口测试通过；HP P1106 的 Windows 驱动可以由 Python 调用。

推荐流程：

```text
浏览器 React
  → FastAPI：用户认证、文件权限、上传、任务提交与查询
  → 文件存储 + SQLite：原件、标准 PDF、用户、任务记录
  → 独立转换进程：Office → LibreOffice → 标准 PDF
  → 预览进程：PDF → 页面图片，或浏览器 PDF 查看器
  → 单个打印工作进程：PDFium → RGB 图像 → GDI → HP 驱动 → USB001
  → Winspool：任务编号、状态查询、暂停/恢复/取消
```

当前最直接的打印路径已经测试：**pypdfium2 + Pillow ImageWin.Dib + Windows GDI**。可避免依赖 PDF 文件关联和桌面打印对话框，并取得 Windows JobId。

向 HP 实际提交了一张 A4、单面、单份中文测试页，任务编号 **33**；驱动接受任务并进入打印状态，约 9 秒后任务从队列消失。**用户随后确认：“已出纸，中文和图形正常”。因此本次单页打印链路已通过实际纸面验收。**该确认不包含尺寸测量或其他纸型/多页测试。

**不要依赖系统默认打印机。** 同期 `Win32_Printer.Default` 指向远程桌面重定向 PDF 队列，而 Python `GetDefaultPrinter()` 返回 HP。两个接口结果不一致，本次没有修改默认打印机；其原因未确定。项目配置必须使用明确的 HP 队列名称，并排除 `TS001` 等远程重定向端口。

HP 官方规格说明：P1106 为 **Host-based printing**，USB 连接，无原生网络/无线能力，只有手动双面。直接把任意 PDF/文本字节通过 `WritePrinter(..., RAW)` 发给它，不是 PDF 渲染打印方案。GDI 路径产生的最终驱动数据可以被标为 RAW，这与直接发送 PDF 原始字节是两回事。[HP P1106 官方规格](https://support.hp.com/au-en/product/product-specs/hp/5099192)、[Microsoft RAW 数据类型](https://learn.microsoft.com/windows-hardware/drivers/print/raw-data-type)

### 可打印区域

| 纸张/方向 | 物理像素 | 可打印像素 | DPI | 物理尺寸 mm | 可打印尺寸 mm | 左/上偏移 mm |
|---|---|---|---|---|---|---|
| A4 纵向 | 4961 × 7016 | 4800 × 6827 | 600 × 600 | 210.016 × 297.011 | 203.200 × 289.010 | 3.979 / 3.979 |
| A4 横向 | 7016 × 4961 | 6827 × 4800 | 600 × 600 | 297.011 × 210.016 | 289.010 × 203.200 | 3.979 / 2.836 |
| A5 纵向 | 3496 × 4961 | 3328 × 4772 | 600 × 600 | 147.997 × 210.016 | 140.885 × 202.015 | 3.979 / 3.979 |

这些数值来自真实设备上下文 `GetDeviceCaps`，不是纸张标称值。默认 GDI 原点对应可打印区域；实现“实际尺寸”与纸面坐标时，要正确处理 PHYSICALOFFSETX/Y。本次样例使用等比例缩放到可打印区域，会略微缩小整张 A4 PDF。

驱动枚举到 18 种纸张，包括 A4(9)、A5(11)、A6(70)、Letter(1)、Legal(5)、B5(JIS)(13)、16 开及信封。未实测这些纸型的实际进纸。使用纸张 ID 和尺寸作为稳定字段；读取本地化纸名使用 `DeviceCapabilitiesW`。完整数组在 `python_printer_probe.json`。

### 驱动返回值需要校正

- DC_DUPLEX=1，PrintCapabilities XML 包含长边/短边双面，且 DocumentProperties 接受 Duplex=2；这不证明存在自动翻面硬件。平台第一版建议仅开放单面，手动双面另建需要人工翻纸的流程。
- DC_BINS 返回自动选择、手动进纸、纸盘 1/2/3。这些属于驱动声明，不能直接向用户宣传存在多个物理纸盘；第一版使用自动选择。
- DC_ENUMRESOLUTIONS 在本机报 Win32 错误 2；默认 DC 可成功返回 600 DPI。不要因枚举失败认定打印机不可用，也不要凭该结果承诺更多分辨率。
- DEVMODE 包含 820 字节厂商私有数据，总缓冲 1040 字节。应从现有驱动取得 DEVMODE，在保留私有数据的基础上修改公开字段，再用 DocumentProperties 校验。
- A4、A5、横向、2 份与 Duplex 请求的校验/DC 创建成功；除 A4 单面 1 份外，其他参数未做实际出纸测试。
- 校验的是每个任务的 DEVMODE 副本，队列默认设置前后相同。

本机 pywin32 的 `PyCDC.StartDoc()` 返回 None，第一次虚拟测试因此未取得 JobId，但 PDF 输出成功。脚本已改为调用原生 **gdi32.StartDocW**，其返回值为有效 JobId，再使用 GetJob/SetJob 管理。第一次记录保留在 `print_virtual_first_attempt.json`，后续记录为修正后的结果。

任务 33 观察到的主要状态位：8=正在后台处理；9=后台处理+暂停；1=暂停；0=无标志；8208=0x2010，包含 PRINTING 与 COMPLETE。PagesPrinted 在移除前一直为 0，因此它也不能作为可靠出纸计数。

Microsoft 文档明确指出 COMPLETE 可表示任务已经发送到打印机但尚未打印；部分端口监视器对 PRINTED 也存在提前标记的限制。平台应区分“已提交”“正在打印”“队列已结束”和“用户确认完成”，保留原始 Status 位；GetJob 返回 87 且 EnumJobs 中不再存在该 JobId，可用于确认队列记录已移除，但不能单独推断成功还是取消。[Microsoft JOB_INFO_2](https://learn.microsoft.com/en-us/windows/win32/printdocs/job-info-2)

打印相关 API 可能阻塞，放在独立 worker 中；FastAPI 不应在 async 请求函数中直接长时间调用打印驱动。每个 worker 单独打开并关闭打印机句柄，保存 JobId 后再响应任务状态。[Microsoft StartDocPrinter](https://learn.microsoft.com/windows/win32/printdocs/startdocprinter)、[FastAPI 并发文档](https://fastapi.tiangolo.com/async/)

SumatraPDF 3.6.1 可作为备选外部打印器，本次仅验证失败路径，没有额外向 HP 打印。当前官网文档包含新版的分级退出码及参数，不能直接假定本机 3.6.1 具备全部新特性；本机两项失败测试均返回 1。正式集成使用参数列表、固定程序/队列、超时和返回码，避免 ShellExecute 或系统文件关联；外部进程返回成功也不等于已经出纸。[Sumatra 命令行文档](https://www.sumatrapdfreader.org/docs/Command-line-arguments)

调用模板（Python 中应作为 subprocess 参数数组）：

```text
C:\Program Files\LibreOffice\program\soffice.com
-env:UserInstallation=file:///C:/.../独立profile目录
--headless --nologo --norestore
--convert-to pdf --outdir 输出目录 输入文件
```

独立 profile 避免复用用户桌面正在运行的 LibreOffice。每个转换 worker 独享 profile，输入/输出目录可写；转换先设 120 秒超时，再结合实际负载调节。检查返回码、输出存在性、非空、可被 PDF 解析器打开和页数，不能只查 exit code。[LibreOffice 官方参数文档](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

Writer/Impress 转换 stderr 出现 `Could not find platform independent libraries <prefix>`，但返回码 0、输出存在且能正确读取中文；本次将其记录为警告。第一次脚本错误来自终端 GBK 无法编码日志中的替换字符，不是转换失败；已显式配置 UTF-8 stdout，并按 gb18030 解码本机 LibreOffice 输出，修正后重跑。

Office 已安装，但未使用 Word/Excel COM 作为后端转换方案。无人值守/服务环境需考虑 Office 的对话框、用户配置和自动化支持范围，优先采用已经验证的 LibreOffice headless。[Microsoft Office 无人值守自动化注意事项](https://learn.microsoft.com/en-us/office/client-developer/integration/considerations-unattended-automation-office-microsoft-365-for-unattended-rpa)

PyMuPDF 与 PDFium 的中文页面预览均通过。PyMuPDF 在单个简单 A4 测试页上的 RGB 像素缓冲如下：

| DPI | 图像像素 | 仅 RGB 缓冲大小 |
|---|---|---|
| 96 | 794 × 1123 | 2.67 MB |
| 150 | 1241 × 1754 | 6.53 MB |
| 300 | 2481 × 3508 | 26.11 MB |
| 600 | 4961 × 7016 | 104.42 MB |

这些不包含解码、Pillow、DIB、驱动与进程的额外内存。8 GB 主机应逐页渲染/释放，预览 96–150 DPI，初始打印栅格 300 DPI，再以实际纸面质量调整；不要一次把所有页渲染为 600 DPI 图片。复杂/扫描文档的性能未测。

PDF 页码选择 [3,1] 已生成 2 页输出并检查顺序正确；PDF 第 2 页横向预览为 1754 × 1241 像素。缩略图、页码选择与打印应基于同一个标准 PDF，避免重新转换产生分页差异。

PyMuPDF 为 AGPL/商业双许可；本次调研使用它生成样本、处理 PDF 和验证接口。正式产品确定许可方案时，可选已经验证的 pypdfium2 作为主要渲染器，其项目为 Apache-2.0/BSD-3-Clause，PDFium 及第三方依赖也有各自许可需保留。PDFium 不支持并发线程任意调用，应使用进程隔离或全局互斥；此限制也支持采用独立渲染 worker 的设计。[PyMuPDF 许可说明](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright)、[pypdfium2 项目](https://github.com/pypdfium2-team/pypdfium2)、[PDFium 线程说明](https://pypdfium2-team.github.io/pypdfium2/python_api.html)

## 8. 后续实现建议与接口草案

建议第一阶段支持 PDF、PNG、JPEG；第二阶段启用经 LibreOffice 转换的 DOCX/XLSX/PPTX。文件上传返回 file_id 和状态，转换异步完成，预览完成后允许提交打印任务。转换任务初次可慢至近一分钟，不应占着 HTTP 请求等待。

| API | 用途 |
|---|---|
| POST /api/auth/login、logout | 登录、退出 |
| GET /api/auth/me | 当前用户 |
| POST /api/files | 上传，返回 file_id 与处理状态 |
| GET /api/files/{id} | 所属用户的格式、页数、状态 |
| GET /api/files/{id}/pdf | 所属用户标准 PDF，支持 Range |
| GET /api/files/{id}/preview/{page} | 所属用户预览 |
| GET /api/printers | 返回允许使用的 HP 队列及校正后能力 |
| POST /api/print-jobs | 指定 file_id、页码、份数、纸张、方向、缩放，返回应用 job_id |
| GET /api/print-jobs/{id} | 应用任务状态 + Windows JobId 和原始状态 |
| POST /api/print-jobs/{id}/cancel | 所属用户取消；仅对自己的 Windows 任务操作 |

核心任务字段建议包含 owner_id、file_id、标准 PDF 哈希、打印参数 JSON、幂等键、队列名、Windows JobId、worker_id、状态、提交/结束时间、原始 Win32 错误及状态快照。打印请求点击重复或网络超时，不应自动重发纸张；如果已取得 JobId，应先核对队列/应用记录，结果不明转为 unknown 并等待人工决策。

单台 USB 打印机先采用 **一个打印 worker**，有持久化应用队列；多个 API worker 不应分别消费并重复提交。任务取消可能无法撤回设备已经收到的页面，界面应显示实际取消结果，而不是仅本地把状态改成 cancelled。转换/渲染单独限并发与超时，预览缓存按标准 PDF 哈希、页码、DPI 保存。

使用 UUID 做落盘文件名，保留原始文件名仅作显示；检查扩展名、文件签名、解析结果、大小、页数和像素数。预览/PDF 下载仍需身份和 owner 校验。不要把原始上传目录公开为静态目录；提供可控保留期、数据库与文件一致性清理、打印记录与异常日志。
