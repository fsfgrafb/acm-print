# 新版本项目设计讨论

更新日期：2026-10-14，Asia/Shanghai。

本稿保留为讨论来源。正式实施基线已整理至 [新版设计文档](docs/v2/README.md)，以该目录为准。本文不授权实现、部署或修改旧版。环境事实以《环境调研报告.md》为依据；旧源码仅提供功能线索，不自动构成新版本需求。未确认的选择明确标为待确认。

## 1. 已确认范围

- 完全重构，不兼容旧版，不迁移旧版数据。旧项目将由用户删除，本轮不执行删除。
- 完全移除每日配额、超额审批及其相关流程，只做详细记录。
- 不继承用于配额管理的跨账号拆页提醒。
- 每个账号创建成功起，有效期固定四年，到期删除账号，并同时删除该账号的打印记录。新用户由管理员 CSV 导入，不开放自行注册。
- 自定义页码保留输入顺序并允许重复，例如 `3,1,3` 按第 3、1、3 页打印三页。
- 第一版支持 PDF、PNG/JPG/JPEG/BMP、TXT、DOC/DOCX、XLS/XLSX、PPT/PPTX。支持多文件批量提交、奇数/偶数页和多份打印；纸张与单双面限定为 A4 单面。
- 多份采用逐份打印，份数上限默认 20 份，可由管理员在管理页修改。类似数值参数按可管理配置设计，当前讨论给出的数字是默认值。
- 打印默认纵向、实际尺寸；每个任务提交前可调整方向和缩放，相关高级设置默认收起。选页区域直接显示奇数页、偶数页和自定义页码选项。
- 批量文件按页面列表顺序打印，允许拖动排序；每个文件独立设置页码和份数、生成独立任务。
- 预览必须显示应用奇数/偶数页或自定义页码后的实际页面结果，保留自定义顺序和重复页面。
- 用户报告的现场行为：缺纸等异常发生后，需要补纸并在部署机器的驱动弹窗点击“继续”；异常解除后应自动恢复正常调度。
- 当前全部工作仅限新版本项目文档。
- 技术栈已确定：React + TypeScript、Tailwind CSS、Python FastAPI、PostgreSQL。具体版本和组件库尚未确定。
- 界面简洁实用，以打印操作和队列信息为主；需要手机适配，暂不需要深色模式。具体配色待确认。

## 2. 已确定数据库：PostgreSQL

已由用户确认使用 PostgreSQL。选型理由是持久化任务与事件记录、事务一致性，以及 API、转换、打印等不同进程协调更容易形成清晰的边界。数据库更换本身不能修复混乱的状态机。

初期可以与应用部署在同一 Windows 主机，不因选用 PostgreSQL 就引入额外服务器或容器。8 GB 主机需要同时控制文档渲染内存、数据库连接池和转换并发；不能只根据内存总量承诺性能。当前报告没有 PostgreSQL 安装、运行或故障恢复实测证据。

部署文档需补充数据库 Windows 服务、运行账号、仅本机数据库连接、最小权限应用账号、连接池上限、数据库迁移与备份恢复。具体 PostgreSQL 大版本和安装包需针对 Windows 10 IoT LTSC 19044 验证后锁定，不能直接把官方 Windows 安装包存在视为本机已兼容。

文件保存在受控文件目录；数据库保存元数据、哈希和任务记录，初期不建议把原件与页面图片直接存入数据库。数据库和文件备份需有一致性方案；单独 pg_dump 不包含外部文件。

参考：
- [PostgreSQL Windows 下载说明](https://www.postgresql.org/download/windows/)
- [pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html)

## 3. 异常恢复语义

应区分两个独立维度：设备是否阻塞，以及某次任务是否已提交。缺纸等待并不等于提交结果不确定。

1. 已取得 Windows JobId、作业仍存在且缺纸：保留原作业，记录等待原因；补纸并在驱动点击继续后，继续跟踪同一个作业，不重新提交 PDF。
2. 设备异常已解除：自动恢复对现有作业的跟踪与后续任务调度。打印 worker 串行提交。
3. 应用在提交与保存 JobId 之间崩溃，或调用超时导致提交结果未知：先尝试依据任务唯一标记和队列记录进行对账。设备恢复正常只说明设备阻塞解除，不能证明这次 PDF 是否已经提交。
4. 作业消失：记录队列结束事实；单凭消失不能区分成功、外部取消、队列清空等原因。不默认自动重发。

用户对现场缺纸恢复的说明修正了此前把所有异常都视为需人工解除应用暂停的建议。自动恢复正常调度与自动重新提交结果未知的任务必须分别定义。未知任务无法对账时的处置策略待确认。

记录建议包括应用任务 ID、提交尝试 ID、唯一文档标记、队列名称、Windows JobId、请求参数、原始状态位、错误码及带时间戳的状态事件。固定打印 worker 也需要防止意外启动第二个实例。

## 4. 碳粉与设备状态：已知边界与待调研项

P1106 是激光打印机，文档应使用“碳粉不足/耗尽”，而非“缺墨”。Windows PRINTER_INFO_2 定义 TONER_LOW、NO_TONER、PAPER_OUT、PAPER_JAM、OFFLINE、USER_INTERVENTION 等状态；API 定义某个状态不代表本机驱动会可靠报告它。

环境报告只验证了双向通信配置开启，尚未验证耗材遥测。设计应保留三种可用性：能报告、不能报告、尚未验证。状态读取失败或无耗材信息应显示未知；不能默认显示碳粉充足。

第一阶段可设计为读取队列/作业状态并保存原始证据，必要时接受人工反馈“字迹淡、空白、卡纸”等。仅在实测可靠后开放碳粉告警；精确百分比、预计剩余页数目前没有证据支持。碳粉低与耗尽是否阻止新任务需要用户确认，不能默认等同处理。

待调研：现有 HP 驱动/工具是否显示耗材信息；信息通过何种接口提供；补纸、驱动继续、USB 断连、断电、卡纸后状态与 JobId 如何变化；重启或无人登录时驱动弹窗能否完成处理。本轮仅列出验证项目，不执行测试。

参考：[PRINTER_INFO_2](https://learn.microsoft.com/en-us/windows/win32/printdocs/printer-info-2)、[JOB_INFO_2](https://learn.microsoft.com/en-us/windows/win32/printdocs/job-info-2)。其他带有 P1106 名称或 Plus 后缀的 HP 支持页面不能未经型号核对直接套用于当前设备。

## 5. 四年账号有效期

已确认期限固定为四年，到期删除账号。新用户由管理员 CSV 导入，已确认从正式导入成功时起算，不从上传 CSV、预览或首次登录时起算。建议按四个日历年计算，不用 1460 天替代。存储 created_at、expires_at，使用带时区时间戳；日期展示采用 Asia/Shanghai。

到期删除账号应使其登录会话失效，并同时删除该账号的打印记录，这是已确认规则。封禁单独保留，不代替四年到期删除。详细记录仅覆盖尚未删除的数据；统计和 CSV 导出不得被描述为永久保留所有账号历史。

持久化保存原件、首次转换的标准 PDF 和实际打印的有序页码列表，选页后 PDF 按需生成并缓存。账号到期时连同打印记录及其关联文件一起清理；共享文件的物理删除须确认已无其他记录引用。备份副本的清理规则尚未确认。删除运行库记录不等于删除已有备份；恢复备份时如何避免已到期数据重新出现需另行定义。正在打印的任务到期时如何处置仍待确认。

已确认从正式导入成功时开始四年倒计时；重复导入已有学号跳过，不重置密码、不延长有效期。唯一管理员到期未交接时暂缓删除，直至完成交接。部署机器提供本地强制转让管理员的功能，用于管理员忘记密码等情况；操作资格、交互方式及交接后过期原管理员的清理时机待定义。该恢复入口不应直接作为公开的无认证 HTTP 接口。

待确认：闰日创建的到期日期；到期前已排队或正在打印的任务如何处理；是否提前通知。新账号不能仅因学号相同自动取得已删除账号的历史文件权限。

### 6.1 CSV 导入页面

## 7. 还需明确的产品问题

- 支持格式已确定为 PDF、PNG/JPG/JPEG/BMP、TXT、DOC/DOCX、XLS/XLSX、PPT/PPTX；各格式转换验收要求需在后续文档中定义。
- 多份采用逐份打印，份数上限默认 20 份，由管理员修改；第一版仅 A4 单面，不提供其他纸型或手动双面流程。默认纵向、实际尺寸；方向与缩放可在提交前逐任务设置。
- 历史只记录成功提交至系统打印队列的任务，展示学号、时间、文件名（仅管理员）、总页数及打印 PDF。总页数为选页后页数乘以份数，重复页码计入页数；不能宣称具有准确物理出纸统计。
- 已确认用户可取消自己的排队任务；管理员可取消任何排队任务并暂停整个应用队列。有已确认的接口支持时，也开放正在打印任务的取消；取消成功不承诺撤回已经出纸部分。
- 文件大小、页数、像素数、个人临时空间和并发限制属于资源保护，不属于已删除的每日打印配额。
- 登录注册、密码找回、账号四年期限以及管理员权限需要统一设计。
- 不限定实验室内网访问，所有业务操作须登录；HTTPS、跨设备验收、开机自启与运行账号需补充部署要求。部署机器长期保持 Windows 用户登录。
- 数据与文件保留期、数据库及文件备份、恢复验收和日志保存期限待确认。

## 8. 候选数据边界

文档设计可先围绕学号主体、登录会话、原件及其授权引用、派生 PDF 缓存、转换任务、运行中打印任务、提交尝试、简化打印历史、系统配置划分实体。打印任务保存有序页码列表和份数。具体表结构待定义，不继承旧版表结构，不包含配额或审批实体。恢复所需状态属于内部运行信息，不自动纳入长期详细历史；内部日志保留期待确认。

## 9. 选页、预览与打印一致性

已确认：用户调整全部页、奇数页、偶数页或自定义页码后，预览必须展示选页后的结果，不能只在原文预览旁显示设置文字。自定义 `3,1,3` 的预览依次展示原文第 3、1、3 页，输出页数为 3。

设计建议：先生成标准 PDF，再将选页表达式展开为有序页码列表；列表允许重复，不使用集合排序或去重。预览与打印共同使用这一列表对应的输出版本。设置变更时使旧预览失效；显示预览处理中或失败状态，避免将旧结果误当成新结果。提交时冻结文件版本和参数，打印 worker 使用已确认的同一版本。

建议页面同时显示输出页位置和原文页码，例如“输出第 2 页 / 原文第 1 页”，便于核对顺序和重复。重复页面须计入输出页数；份数另存，并区分每份输出页数与计划总页数。计划总页数不等同于设备实际出纸计数。

已确认多份采用逐份顺序，例如选页 `3,1`、两份输出 `3,1,3,1`。批量文件允许拖动排序，按列表顺序打印，每个文件独立设置并生成独立任务。手机界面也需提供可用的排序操作；建议除拖动外提供上移/下移按钮。

待确认：自定义范围表达式的具体语法。方向、缩放与可打印区域应在打印预览中一致体现；实际尺寸不自动缩小，超过设备可打印边界的内容可能裁切，预览应反映这一结果。

## 10. 管理页数值配置

已确认：类似份数上限的数值参数由管理员在管理页自由修改，讨论中的数字只作为默认值。份数上限默认 20 份。候选配置包括上传大小、单文件页数、批量文件数量、临时空间、保留期、超时、轮询间隔和转换并发；具体字段与默认值尚需整理，不自动照搬旧版。

此前明确的账号固定四年有效期暂保持固定业务规则，不因本次数值配置要求自动改为可调整。若希望四年也只是默认值，需用户明确修订。

设计建议：配置持久化于 PostgreSQL，管理页显示当前值、单位、说明与默认值；保存时由服务端校验数据类型、合法范围与参数关系，错误须明确显示。自由修改意味着管理员无需改源码或编辑配置文件，并不意味着接受负数、零并发等无效值。

配置变更记录管理员、时间和前后值。新提交按当前配置校验；已提交任务保留当时的参数快照，不因降低份数上限而修改已排队的任务。页面显示哪些设置立即生效、哪些等待当前任务结束或需要重启。保留期缩短所触发的清理行为需另外明确，不能把配置保存动作隐式等同于立即删除数据。

## 11. 最新确认的架构与操作规则

### 11.1 学号与权限

用户可见的所有“用户名”“账号”名称统一为“学号”，系统没有另一个独立用户名概念。内部仍需使用稳定 ID，避免学号删除再导入时错误继承文件和权限。初始密码及管理员重置密码均为学号，首次登录确认改密允许原密码不变。

仅一个管理员，可正常交接，也可在部署机器本地强制转让。首任管理员学号由首次打开前端时填写；初始密码为学号，要求改密，密码至少 4 位；本地恢复采用命令行工具。QQ、电话与管理员联系方式保留。

### 11.2 文件与空间清理

用户已修订此前仅保存选页后 PDF 的规则：长期保存原件、首次转换的标准 PDF 及实际打印的有序页码数字，允许重复；点击预览时按相同选页方式动态生成 PDF 并缓存。打印、预览和打印 PDF 下载复用同一派生流程。派生文件属于可重建缓存，缓存保留和淘汰策略待定义。“实际打印使用”指提交给打印系统的文件，不表示已经确认每页物理出纸。

设计建议：原件不可变，任务记录原件哈希、转换版本、有序页码和份数。派生缓存键包含原件版本、转换版本、有序页码及影响页面内容的参数，`3,1` 与 `1,3`、`3,1,3` 必须是不同结果。已确认保存首次转换的标准 PDF，历史预览和补打基于该标准 PDF，不随未来 Office 转换环境变化重新分页。原始 PDF 可作为其标准 PDF，避免重复保存相同字节。

管理员有权下载所有人的原件与打印 PDF，并预览打印 PDF；普通用户可下载自己的原件与选页后打印 PDF。共享列表对普通用户隐藏文件名和预览，包括本人条目的列表显示；是否另提供本人预览入口待确认。

已确认空间最大阈值按 PostgreSQL 与已保存打印文件的总占用计算，默认 512 GB；上限和清理目标比例均可由管理员修改。超过后按最早提交时间清理已结束任务，直到降至上限的 90%；活动任务不清理。文件保存方案已调整为原件与派生缓存，因此空间计量需覆盖原件、标准 PDF 和派生缓存，不能因文件类型调整而漏计。

设计建议：共享原件或缓存最后一个引用解除后才物理删除，活动任务所需文件保持保护。已确认先清理可重建的闲置预览缓存，仍超限再按最早提交时间清理已结束历史至目标水位。首次标准 PDF 为持久化资料，不作为闲置预览缓存淘汰。清理批次大小、无法释放空间时是否拒绝新提交待定义。不能假定删除 PostgreSQL 行后数据库物理文件立即缩小。

### 11.3 重复上传与再次打印

批量转换失败时允许提交其余成功文件。支持哈希去重与已保存内容复用，以加速重新上传；匹配已有内容不自动打印，也不授予他人文件访问权。

新保存方案允许按原件哈希复用已保存原件，并重新选择其他页码。物理内容去重与访问授权独立：不能仅凭哈希授予他人原件访问权，跨学号查重范围及证明文件持有的方式待定义。浏览器哈希只能作为查重线索，新上传内容仍需服务端核验。

再次打印或部分补打返回打印提交页，使用保存的原件并预先填好原文页码，不直接触发打印；确认后创建新任务并关联原任务。预览仍需区分输出位置和原文页码，避免重复页码造成歧义。

### 11.4 队列与故障处理

打印机异常阻塞打印队列；设备异常解除后自动继续原作业和正常调度。任务自身失败且打印机正常时不阻塞后续任务。真正无法确认提交结果时保留未知状态并继续其他任务，由管理员决定是否补打，不自动重发未知任务。

用户及管理员的在印取消仅在底层接口支持并完成对应能力验证后开放。环境报告已验证自有暂停作业删除，尚未验证已经进纸时的完整取消行为。应用队列暂停表示停止提交后续任务，不自动等同于暂停设备内已有作业。

常规结束状态使用“队列已结束”，不要求每次确认出纸，有问题时用户反馈。共享历史只覆盖尚未被到期/空间清理删除的记录。

### 11.5 平台与系统边界

第一版为一台 Windows 主机、一台固定队列 `HP LaserJet Professional P1106`。打印任务明确关联该队列，禁止依赖系统默认打印机。

可能未来迁移到 Debian。操作系统交互与业务规则解耦：打印适配层负责提交、查询、取消与能力报告，Windows 实现使用已调研链路；未来 Debian 适配需另行验证。转换及文件处理同样避免把平台路径和进程管理写入业务层。初期无需实现 Debian 部署或额外打印机功能，但不把 Windows JobId 当作跨平台业务任务 ID。

Windows 长期保持用户登录，以供现场处理驱动继续弹窗；跨桌面会话与开机启动仍需验收。不限制仅内网访问，登录是业务访问前提；公网域名、HTTPS 和部署入口方案尚未确认。

## 12. 已确定页面结构

登录后普通成员有“提交打印”“任务队列”“个人设置”三个页面。管理员另有“用户管理”“系统管理”两个页面。

- 提交打印：上传、批量排序、逐文件设置、选页后预览与提交；再次打印/补打回到此页。
- 任务队列：当前任务与全部尚未清理的历史；按角色限制文件名、预览、下载和任务操作。
- 个人设置：个人信息与密码相关操作；具体字段待定义。
- 用户管理：CSV 提示、上传预览和导入，学号管理、封禁、重置密码及管理员交接。
- 系统管理：可修改的数值配置及系统运行相关管理；统计和 CSV 导出的具体位置待确认。

总页数已确认采用“选页后页数 × 份数”，例如 `3,1,3`、两份记录 6 页。该页面结构不自动确认普通用户在共享任务列表中的本人预览权限；此前列表文件预览仅管理员可见的规则仍保留。

## 13. 已确认的任务、权限与提交规则

用户已采用以下建议，作为后续正式需求、权限矩阵和数据模型的依据：

1. 成功提交以取得系统 JobId 为依据，写入正常打印历史；“队列已结束”不等同于确认物理打印成功。提交结果未知的任务保留内部恢复信息，不计入正常打印统计；正常设备状态下不阻塞后续任务。
2. 管理员手动暂停必须由管理员手动恢复；设备故障造成的自动阻塞在异常解除后自动恢复。两种原因独立保存；设备恢复不能解除管理员手动暂停。用户取消本人任务，管理员取消任何任务，在印取消按底层支持及验收能力开放，显示实际取消结果。
3. 首先支持同一学号重复上传免传；跨学号可共享物理存储但授权独立，不能仅凭哈希访问他人文件。浏览器查重与服务端内容验证按不同职责设计。
4. 清理闲置缓存、清理最早已结束历史后仍无法获得足够空间时，拒绝新上传并明确提示。活动任务及其依赖文件受保护。空间检查覆盖上传、转换和派生过程中的临时增长，防止实际磁盘写满。
5. 部署机器提供本地命令行工具，将管理员强制转让给已存在且未封禁的学号；原子完成角色转让并撤销原管理员登录会话。操作限于获准使用本地恢复工具的部署机器操作者。首任管理员由首次前端设置页填写学号并原子初始化。
6. 普通学号到期立即禁止登录和新提交，取消尚未提交的任务；已进入系统打印队列的任务待其结束后再删除相关记录与文件。唯一管理员未交接时暂缓删除。结束结果长期未知时如何完成到期清理仍待定义，不能因无限等待而永久保留。

### 13.1 方向、缩放与提交界面

默认 A4、单面、纵向、实际尺寸。每个任务的高级设置默认收起，方向和缩放在其中修改；选页区域直接显示奇数页、偶数页、自定义页码。全部页作为初始选页状态的界面呈现方式待细化，多份输入位置待细化。

方向可选纵向和横向，缩放提供实际尺寸及适合可打印区域；这两项属于用户采用此前建议后的设计落地。实际尺寸保留物理比例，不自动将整页缩小至可打印区域。预览需要使用目标 A4 方向及真实设备可打印区域，并正确处理设备物理偏移；超出边界的内容以实际裁切结果呈现。打印参数在确认提交时冻结。

### 13.2 提交幂等与批量顺序

已确认一次批量提交使用幂等键，双击提交或超时后以同一键重试返回同一次提交结果，不重复创建任务或重复出纸。幂等键关联学号及完整请求参数；同键不同参数应拒绝并提示冲突。明确发起新的打印操作使用新键。

保存批次 ID、文件列表顺序及逐文件任务 ID。队列按批次提交顺序和批内列表顺序调度，不因转换完成顺序打乱用户排列。数据库事务与唯一约束负责幂等持久化，不依赖单个 API 进程的内存锁。幂等结果保留时长及与历史清理的关系待在数据生命周期文档中定义。
